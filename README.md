# Tutorial Schematic 1.2

Мод для Minecraft **26.2** (Fabric): размечаешь готовую постройку по слоям, настраиваешь
формулами, в каком порядке блоки будут появляться, и запускаешь автопостройку — её и снимаешь
на Flashback.

Смысл в том, чтобы не строить дом второй раз ради записи. Строишь один раз, размечаешь, сносишь
одной командой и «проигрываешь» постройку столько раз, сколько нужно ракурсов.

---

## Быстрый старт

Всё делается из меню — **клавиша `G`**. Команды дублируют то же самое, если удобнее макросами.

1. Построй постройку обычным способом.
2. `G` → **Новая** → название.
3. `G` → **Выдать инструмент** (blaze rod). Разметка работает только с ним в руке,
   и пока он в руке — блоки не ломаются.
4. **+ Новый слой** → название (Фундамент, Стены, Крыша…). Закрой меню и кликай **ПКМ**
   по блокам — добавить, **ЛКМ** — убрать. `V` меняет режим выделения. В углу экрана видно,
   какой слой набирается, сколько в нём блоков и что делают кнопки.
4. `G` → **+ Новый слой** для следующего этапа. И так далее.
5. `G` → **Настроить анимацию** — формулы порядка постройки и живое превью.
   В превью: ЛКМ крутит, колесо приближает, **ПКМ ставит точку старта** для формул с `d`.
6. `G` → **Сохранить**.
7. `G` → **Снести постройку**. Включи запись во Flashback.
8. `G` → **▶ Запустить** — меню закроется, постройка пойдёт.

## Рабочий процесс целиком

Слой — это **произвольный набор блоков**, а не горизонтальный срез: в один слой можно положить
все окна во всём доме или всю мебель на всех этажах.

**Порядок слоёв** = порядок в списке слева. Двигают его стрелками `▲` `▼` прямо в строке слоя.
Там же переключается видимость (глазик) и удаление (`✕`, два клика для подтверждения).
Двойной клик по выбранному слою — переименовать.

**Нужен другой ракурс?** Выбери слой в списке и нажми **↺ Откатить к выбранному слою**:
предыдущие слои восстановятся мгновенно, выбранный и все следующие снесутся, постройка встанет
на паузу. Ставишь камеру, жмёшь `P` — и снимаешь этот кусок заново.

## Формулы: как это работает

Каждый блок слоя получает **число** по формуле. Блоки ставятся **по возрастанию** этого числа.
Всё. Любая анимация — это подбор формулы.

Если у двух блоков число совпало, их разводит **следующий уровень сортировки** — как в таблицах:
«сначала по y, потом по a, потом по r». Поэтому не нужно домножать слагаемые на большие числа,
чтобы задать приоритет.

### Переменные

| | |
|---|---|
| `x`, `y`, `z` | координаты блока внутри слоя, от 0 |
| `X`, `Y`, `Z` | размеры слоя (то же самое: `sx`, `sy`, `sz`) |
| `cx`, `cy`, `cz` | центр слоя |
| `dx`, `dy`, `dz` | смещение блока от центра |
| `r` | расстояние от центра по горизонтали |
| `r3` | расстояние от центра в 3D |
| `a` | угол вокруг центра, 0..360 градусов |
| `rand` | стабильное случайное 0..1, своё у каждого блока |
| `i`, `n` | номер блока в наборе и общее их количество |
| `wx`, `wy`, `wz` | абсолютные координаты в мире |
| `d` | расстояние **по самой постройке** от точки старта, шагами |

Имена регистрозависимы: `x` — координата, `X` — размер.

### Операторы

`+ - * / %` · `^` степень · `< <= > >= == !=` сравнение · `&& || !` логика ·
`условие ? да : нет` · постоянные `pi`, `e`, `tau`

**Сравнения дают 1 или 0**, поэтому их можно складывать и умножать — так задаётся приоритет
внутри одной формулы: `(y > 4) * 100 + x`.

### Функции

`abs sign sqrt floor ceil round frac min max clamp hypot dist pow mod log log2 log10 exp
sin cos tan asin acos atan atan2 sinr cosr tanr atan2r deg rad lerp step smoothstep if hash noise`

**Углы везде в градусах**: `sin(90)` равно 1. Для радианов — варианты с `r` на конце.

### Готовые анимации

Кнопка «Пресеты» в редакторе подставляет формулы в поля — их видно и можно править.

| Анимация | Формулы |
|---|---|
| Снизу вверх | `y` |
| Сверху вниз | `y` ↓ |
| Слоями по кругу | `y` → `a` |
| Диагональю | `x + z` |
| Змейкой | `y` → `z` → `mod(z,2)==0 ? x : X-1-x` |
| Волной | `x + sin(z*40)*3` |
| От центра наружу | `r` |
| Сферой | `r3` |
| Стрелкой часов | `a` |
| Две полоски навстречу | `min(x, X-1-x)` |
| С четырёх сторон | `min(x, X-1-x, z, Z-1-z)` |
| Спираль внутрь | `min(x, X-1-x, z, Z-1-z)` → `a` |
| Случайно | `rand` |
| Дождь сверху | `-y + rand*3` |
| Проявление шумом | `noise(x*0.3, y*0.3, z*0.3)` |
| Сначала каркас | `(x>0 && x<X-1 && z>0 && z<Z-1) * 1` → `y` |
| Огоньком по постройке | `d` |
| Огоньком с покачиванием | `d + sin(a*2)*2` |
| Огоньком, снизу при равенстве | `d` → `y` |

### `d` — единственная переменная, которая знает про форму

Все остальные переменные считаются **по координатам точки** и о блоках ничего не знают.
Поэтому фронт волны идёт сквозь пустоту так же, как через стену: на обводке крыши или на
арке он в какой-то момент перепрыгивает на другую сторону дома — там просто оказались
блоки с похожим значением формулы.

`d` устроена иначе: это число шагов от точки старта, где шаг возможен **только на соседний
блок того же слоя**. Пути сквозь дырку нет, поэтому фронт обтекает её и идёт по конструкции —
та самая «волна из одной точки», которая ползёт по уже поставленному.

**Точка старта — ПКМ по блоку в превью** (левая кнопка там крутит модель, данные не трогает).
Точек может быть несколько — тогда фронты идут навстречу. Без выбора старт берётся с самого
нижнего блока.

Соседями считаются все 26 клеток вокруг, вместе с диагоналями. Иначе кромка скатной крыши,
где блоки касаются только ребром, рвала бы обход на первом же шаге.

До кусков, не связанных с точкой старта, пути нет — они уходят в конец слоя одной группой,
а между собой их разводит следующий уровень сортировки.

### Ширина шага: по счёту или по фронту

Кнопка **«Шаг: …»** рядом с размером пачки в редакторе анимации.

**По счёту** — ровно столько блоков за шаг, сколько указано. Темп ровный, но фигуру
он не видит.

**По фронту** — за шаг встают **все блоки с одинаковым значением формулы**, и ширину
задаёт сама постройка. Пока фронт идёт одной ниткой, за шаг встаёт один блок; нитка
раздвоилась — пошло по два, обе ветки одновременно; ветки сомкнулись — снова по одному.
Размер пачки при этом ни на что не влияет и гасится.

Это нужный режим для `d`: ветвление по конструкции только так и выглядит правильно.
Хорошо работает и с `y` — тогда за шаг встаёт весь горизонтальный ряд, — и с `r`,
где шагом становится кольцо.

У дробных формул вроде `x + sin(z*40)*3` одинаковых значений почти не бывает, поэтому
режим честно вырождается в один блок за шаг. Значения сравниваются точно, без допуска:
лучше лишний шаг, чем случайно склеенные блоки.

Полная справка с описанием каждой функции — кнопка «Справка по формулам» в редакторе.

## Инструмент разметки

Разметка работает **только пока в руке blaze rod**. Взять его: `G` → **Выдать инструмент**
(или `/tutorial wand`; в креативе кладётся прямо в выбранный слот).

Пока инструмент в руке и разметка включена, **блоки не ломаются** — левый клик уходит
редактору. Убрал инструмент — кирка снова работает как обычно, ничего переключать не надо.

## Режимы выделения

Переключение — клавиша **`V`** (или кнопка «Режим» в меню). Текущий режим и его управление
всегда видны на панели в углу экрана, помнить ничего не надо.

Кнопки везде значат одно и то же, как в самой игре: **ПКМ добавляет, ЛКМ убирает.**

| Режим | Для чего | ПКМ (добавить) | ЛКМ (убрать) |
|---|---|---|---|
| **По одному блоку** | точная правка | блок под прицелом | блок под прицелом |
| **Две точки** | пол, стена, этаж целиком | два клика — коробка между ними | два клика — вырезать коробку |
| **Заливка** | всё из одного материала подряд | залить | убрать залитое |
| **Магнит** | тот же блок через уже размеченное | собрать всё такое | убрать |

Разница между «Заливкой» и «Магнитом»: заливка идёт по соседям и упирается в чужой блок.
Магнит проходит **сквозь то, что уже размечено в этом слое**. Диорит в центре, вокруг кольцо
андезита, за ним снова диорит: отметили центр, отметили андезит — и повторный клик по центру
дотянется до внешнего кольца, хотя по нему не кликали. Чем больше набрано, тем дальше
магнит достаёт.

В «Двух точках» первый клик только ставит угол, а что случится с коробкой — решает **вторая**
кнопка. Так можно обвести область и передумать по дороге.

Обе кнопки работают **протяжкой**: зажал и веди прицелом — блоки добавляются или убираются
подряд. В режиме «Две точки» протяжка отключена, там нужны именно два клика.

Блок не может лежать в двух слоях: если кликнуть по уже размеченному блоку, он **переезжает**
в активный слой, и об этом пишется в сообщении.

## Живой снос

**`G` → «Живой снос»** — размеченный блок сразу исчезает из мира, а вынутый из слоя
возвращается на место. Нужно, чтобы размечать дом насквозь: разметил крышу — она пропала,
под ней стал виден второй этаж, размечаешь его, и так до фундамента. Отдельно сносить
постройку перед съёмкой уже не надо.

При включении сносится всё, что уже размечено во всех слоях. При выключении всё
возвращается в мир. Обе стороны обратимы, так что подтверждения нет.

**Подсветка при этом остаётся** — когда блоков в мире нет, она единственное, по чему видно,
где слой был. Гасится отдельно, клавишей `H` или кнопкой «Подсветка».

Работает только в одиночном мире, как и сама постройка.

## Картины, рамки и стенды

Это **сущности**, а не блоки — они не лежат в сетке мира. Мод берёт их отдельно, но
пользоваться так же:

- **ПКМ по картине или рамке** — добавить в активный слой, **ЛКМ** — убрать.
  Рамка при этом не проворачивается, а стенд не забирает предмет: клик уходит редактору
- **Коробка «Две точки» захватывает их заодно** — обвёл стену, картины на ней попали в слой
  вместе с блоками. В чат приходит отдельная строка, сколько декораций добавилось
- В слое они подсвечиваются рамкой в цвет слоя

Берутся картины, рамки (обычные и светящиеся), стенды с бронёй и дисплеи. Мобы, выпавшие
предметы и лодки намеренно пропускаются — иначе в схему уехала бы случайная корова.

**Строятся в конце своего слоя**, после всех его блоков: картина не висит на воздухе, ей
нужна уже готовая стена. Предмет в рамке, поворот картины и броня на стенде сохраняются.

## Выделение по координатам

Угол коробки можно поставить только на существующий блок — если он приходится на пустоту,
прицелиться не во что. Для таких случаев есть команды:

| Команда | Что делает |
|---|---|
| `/lpos1` | первый угол в клетке, где стоишь |
| `/lpos1 <x> <y> <z>` | первый угол по координатам |
| `/lpos2` | второй угол и сразу добавить коробку в слой |
| `/lpos2 <x> <y> <z>` | то же по координатам |
| `/lpos2 remove` | тем же жестом убрать коробку из слоя |

Первый угол видно в мире зелёной рамкой, как и при обычном выделении.

## Как убрать лишнее

- **ЛКМ** — тем же жестом, что и добавлял. Коробка зацепила соседнюю стену — обведи
  лишнее двумя кликами левой кнопкой, и оно уйдёт из слоя.
- **ЛКМ протяжкой** в режиме «По одному блоку» — стирать отдельные блоки, как ластиком.
- **`G` → «Очистить слой»** — убрать из слоя всё, с подтверждением.

## Меню (`G`)

**Слева — слои.** Клик выбирает, двойной клик переименовывает. В строке: `▲` `▼` порядок,
глазик — видимость подсветки, `✕` — удалить (два клика).

**Справа — действия:**

| Раздел | Что там |
|---|---|
| Схема | Новая · Открыть · Сохранить · Сохранить как · Закрыть |
| Разметка | вкл/выкл · выдать инструмент · режим · очистить слой · показ слоёв · подсветка · живой снос |
| Анимация | переход в редактор формул для выбранного слоя |
| Постройка | Снести · ▶ Запустить · Пауза · Стоп · Достроить · ↺ Откат · скорость · звук |

Сверху — сводка по схеме, снизу — справка по формулам.

## Съёмка через Flashback

Если установлен [Flashback](https://modrinth.com/mod/flashback), мод умеет вести запись сам
и раскладывать по ней камеры. Без него всё остальное работает как обычно, кнопки просто гаснут.

### Как снимать

1. `G` → **Снести постройку**
2. `G` → **● Запустить с записью** — включается запись, мод дожидается слепка мира и только
   потом начинает строить. Ждать нужно обязательно: начнёшь раньше — начало постройки
   в реплей не попадёт
3. По ходу на таймлайн падают **метки по слоям**, с их названиями и цветами
4. Останавливаете запись обычной клавишей Flashback
5. `G` → **Расставить камеры**
6. Открываете реплей — дорожки уже на месте

### Что получается

Пять дорожек:

| Дорожка | Что делает |
|---|---|
| Общий · вся постройка | один кадр на всю запись, вся стройка целиком |
| Дальний · статичный | камера стоит, слой целиком |
| Средний · статичный | камера стоит |
| Ближний · статичный | камера стоит, близко, всегда режет по сторонам/объектам |
| Средний · ведёт | плавно ведёт прицел за работой, режет редко |

В коде доктрин больше — есть варианты с другой стороны, сверху, ближний ведущий, с движением
камеры (дуга, облёт, наезд, отъезд), — но на практике они стабильно давали больше плохих
ракурсов, чем пользы. Отключены, а не удалены — код и тесты на них живы, при желании можно
включить обратно.

Включаете нужную, остальные глушите.

### Камера меняет ракурс по ходу слоя

Ракурс режется не по слою и не по таймеру, а по **тому, что физически происходит на
площадке**: мод смотрит на полный порядок появления блоков (в том же порядке, в каком их
кладёт сама постройка) и делит его на **участки работы** — сплошные куски, которые держатся
одной формы (пол, столб, стена) и одного направления фронта. Пока кладка идёт по одной
стене — это один участок; стена свернула за угол или сменилась на столбы — начался новый.
Слой тут ни при чём: участок вправе пройти сквозь границу слоя, если фронт там реально не
меняется, и наоборот, один слой-кольцо (стены, экстерьер, крыша) сам собой распадается на
несколько участков — по одному на каждую сторону.

Дальше каждая дорожка собирает эти участки в **сцены** по-своему: дальний план охотно
объединяет соседние участки в один кадр (обошли угол дома — а ракурс тот же), ближний режет
почти на каждом участке. Разница — не в алгоритме, а в допуске на поворот и в максимальном
радиусе сцены; сам алгоритм подбора ракурса общий для всех.

Между сценами — обычно жёсткая склейка: ракурс выбран заново, подъезжать к нему плавно от
старого нет смысла. Исключение — ведущие дорожки: если трасса между концом прошлой сцены и
началом новой физически свободна (проверяется отдельно, по нескольким точкам вдоль прямой),
переезд между ними плавный, а не рез.

Насколько плотно вести, решает дорожка: ближняя целится точно в работу, средняя смешивает
её с центром сцены, чтобы та не выезжала за края. **Статичные дорожки не ведут намеренно** —
неподвижный кадр нужен для склейки и чтобы глазу было за что зацепиться; работа в нём всё
равно видна, просто ходит внутри кадра.

### Как выбирается ракурс

Сначала видимость: из двух десятков точек вокруг пускаются лучи в блоки сцены, и считается,
сколько долетело мимо уже построенного — не только предыдущих слоёв, но и того, что успели
поставить в этом же слое раньше по ходу. Камера, помимо этого, не имеет права оказаться
внутри снимаемого или уже стоящего блока — кандидат с таким совпадением проигрывает поиск
сразу. При пустом дворе видно почти отовсюду, поэтому дальше решает композиция, по правилам
съёмочной практики:

- **три четверти вместо фронта** — в лоб стене постройка выглядит плоско, диагональ
  показывает две стороны сразу;
- **высота из середины диапазона**, а не с края, иначе все планы оказываются на одной линии;
- **разворот между соседними планами не меньше тридцати градусов** — меньше, и склейка
  читается рывком;
- **не перепрыгивать через ось** — план с противоположной стороны переворачивает направление
  движения в кадре;
- **правило третей** — целимся чуть выше центра, постройка садится в нижние две трети кадра;
- **высота зависит от формы слоя** — плоский пол или фундамент с малой высоты виден с торца,
  поэтому над ними камера поднимается; стены, кольца стен и объёмные куски остаются внизу.
  Плоскость считается не по габариту, а по занятости пола: низкое кольцо стен по габариту
  неотличимо от плиты, а по занятости — вчетверо реже, и камера над ним не задирается;
- **если слой не виден снаружи, камера подходит ближе** — интерьер, обнесённый готовыми
  стенами, снаружи не виден ни с какой стороны, и единственный выход это оказаться внутри.

Подъём камеры ограничен сверху у всех дорожек. Геометрически лучший ракурс почти всегда
зенит, но снятое сверху выглядит мёртво.

### Пересобрать камеры заново

Жмите «Расставить камеры» ещё раз — свою же работу мод перезапишет. Узнаёт он её по имени
сцены, «Слои постройки». **Переименуйте сцену в редакторе Flashback, и мод перестанет её
трогать** — так сохраняется ручная правка.

### Оговорки

- **Камеры появляются после остановки записи**, а не во время. Иначе никак: свой счётчик
  тиков Flashback наружу не отдаёт, и опорными точками служат наши же метки — их номера
  тиков он записывает в `metadata.json`
- **Если файл камер для реплея уже есть, мод его не трогает** — там может быть ваша ручная работа
- Формат состояния редактора у Flashback неофициальный. Обновят — экспорт может отвалиться,
  тогда всё остальное продолжит работать, а кнопка скажет об этом

### Команды

`/tutorial record` — запустить с записью, `/tutorial cameras` — расставить камеры.

## Файлы

Схемы лежат в `<папка игры>/tutorial-schematics/*.ltutorial` — **одна папка на все миры**.
Формат — обычный JSON с палитрой состояний блоков, так что файл можно открыть текстовым
редактором и, например, поправить формулу вручную.

**Схема помнит, где её размечали.** В файле лежит абсолютный угол постройки и название мира,
поэтому при открытии слои встают ровно туда, где вы их набирали. Если открыть схему в другом
мире, мод предупредит: координаты там ничему не соответствуют.

Файлы старого формата (до версии 4) абсолютного угла не содержат — такие откроются
в начале координат, как и раньше.

## Ограничения

- **Постройка работает только в одиночном мире.** Мод клиентский и ставит блоки через
  встроенный сервер; на чужом сервере таких прав нет, о чём он честно сообщит.
- Содержимое сундуков берётся из того, что синхронизировано на клиент. Таблички и баннеры
  сохраняются надёжно, содержимое неоткрытых сундуков — нет.
- `/build clear` ставит воздух на месте размеченных блоков. Если постройка стоит не на пустом
  месте, то, что было под ней раньше, не восстанавливается.

## Сборка

Нужен JDK 21 или новее (проверено на JDK 26).

```bash
./gradlew build     # jar в build/libs/
./gradlew test      # тесты движка формул и сортировки
./gradlew runClient # запустить клиент с модом
```

Движок формул и сортировка блоков не зависят от Minecraft и покрыты обычными юнит-тестами.
