# Лаборатория камер

Отдельная программа для подбора и проверки камер **без запуска Minecraft**.

Цикл «правка алгоритма → сборка мода → запуск игры → постройка → запись реплея → рендер видео →
просмотр» занимает часы. Из-за этого алгоритм камер долго правился вслепую, по косвенным числам,
и не раз получалось «по метрикам отлично, глазами плохо». Здесь тот же самый код прогоняется за
секунду, и результат видно глазами.

## Запуск

```
cd camera-lab
..\gradlew.bat --project-dir . run
```

Схема подхватится сама из папки мода (`ModrinthApp/profiles/*/tutorial-schematics`), либо
открывается кнопкой «Открыть схему…».

Числа без окна:

```
..\gradlew.bat --project-dir . build
java -cp build\classes\java\main;<gson.jar> com.tutorialschematic.lab.CameraLab <схема.ltutorial> --report
```

## Что умеет

Три вида, каждый отвечает на свой вопрос:

- **Кадр алгоритма** — ровно то, что попадёт в видео: с letterbox под формат (шортс 9:16, квадрат,
  горизонт 16:9) и с пунктирной рамкой безопасной зоны конкретной дорожки.
- **Со стороны** — постройка целиком, коробка её габарита и **обе камеры как объекты** с лучами
  взгляда: синяя — алгоритма, розовая — ручная. Если камера внутри дома, это подписано прямо в
  кадре. Мышь вращает, колесо приближает.
- **Ручная камера** — свободный полёт: **WASD** лететь, **Q/E** вниз-вверх, мышь оглядеться,
  колесо — скорость полёта.

Остальное:

- **Таймлайн с проигрыванием и скоростью** от 0.1x до 8x (1x — реальный игровой темп, 20 тиков в
  секунду). На медленной скорости хорошо видно, как именно камера ведёт работу.
- Блоки, которые ставятся прямо сейчас, подсвечены жёлтым; если из этого ракурса они не видны —
  красным. Непостроенное показано призраком (отключаемо).
- **Формы** — что анализатор увидел в постройке: слои, куски работы, их форма и направление фронта.
  Полезно, когда алгоритм ошибается в разборе: `BLOB` значит «ни на что не похоже», и такие места
  снимаются хуже всего.
- **Отчёт** — метрики: заслонено при установке, за кадром, вне безопасной зоны, доля кадров с
  камерой внутри постройки.
- Переключение дорожки, формата кадра и FOV — пересчёт мгновенный.

## Правка ракурсов — показать, как надо

Главное, ради чего это писалось. Объяснить словами, каким должен быть ракурс, оказалось труднее,
чем показать: несколько итераций подряд алгоритм чинился по косвенным признакам и промахивался.

Хранится не отдельно стоящая камера, а **пара «выбрал алгоритм / выбрал я» на одном и том же
ракурсе**. По одиночным кадрам не видно, чем именно человек не согласен; по паре — видно сразу.

Как пользоваться:

1. На таймлайне щёлкнуть по полосе **«ракурсы алгоритма»** — ракурсы там пронумерованными
   отрезками, выбранный подсвечен. Справа появятся его параметры: азимут, подъём, дистанция,
   внутри дома камера или снаружи.
2. **«Править ракурс»** — свободная камера встаёт ровно туда, где её поставил алгоритм. Дальше
   **WASD** лететь, **Q/E** вниз-вверх, мышь оглядеться, колесо — скорость.
3. Написать в поле **«Чем этот ракурс лучше»** пару слов — самое ценное поле.
4. **«Сохранить мой ракурс»** — правка ложится под этим же номером, на таймлайне отмечается
   розовым в полосе «мои ракурсы».
5. **«Записать правки в файл»** → `camera-lab/corrections/<схема>__<дорожка>.json`.

Файл пишется в читаемом виде: у обоих ракурсов сохраняется то, что и так вычислимо (азимут,
подъём, дистанция, внутри ли дома), плюс отдельным блоком **разница** между ними. Дублирование
намеренное: закономерность видна по одному файлу, ничего не запуская.

```json
{
  "shotIndex": 2, "tick": 84, "layer": "столбы", "sceneShape": "FLAT", "sceneBlocks": 38,
  "note": "вышел за стену, снимаю снаружи",
  "algorithm": { "x": 1525.4, "y": 133.2, "z": 243.3, "yaw": 120, "pitch": 23.3,
                 "derived": { "azimuthFromCentre": 59.6, "distanceFromCentre": 21.6,
                              "insideBuilding": false } },
  "mine":      { "x": 1517.4, "y": 130.2, "z": 237.3, "yaw": 145, "pitch": 18.3,
                 "derived": { "azimuthFromCentre": 66.2, "distanceFromCentre": 11.5,
                              "insideBuilding": false } },
  "difference": { "turnedByDegrees": 6.7, "raisedByBlocks": -3.0,
                  "movedFurtherByBlocks": -10.1, "distanceRatio": 0.53 }
}
```

Этот файл можно показать ассистенту: из блока `difference`, сопоставленного с `layer` и
`sceneShape`, видна закономерность — «на стенах всегда разворачивает к плоскости», «на интерьере
всегда опускает», «везде выходит наружу». Одна такая закономерность стоит больше, чем десяток
подобранных на глаз весов.

У каждой дорожки свой файл правок: ракурсы у них разные, и сравнивать их между собой нечего.

## Как это устроено (важно)

**Алгоритм не дублируется.** Пакеты `camera`, `order`, `formula` подключаются исходниками прямо из
мода (`../src/main/java`, см. `build.gradle`) — они не зависят от Minecraft. Значит, лаборатория
гоняет тот же самый `BuildAnalyzer`, `ScenePlanner`, `ShotPlanner`, что уходит в реплей, а
картинка строится той же `CameraFraming.project`, по которой алгоритм решает, попал блок в кадр
или нет. Правка алгоритма видна здесь сразу, без копирования файлов.

**Что всё-таки продублировано:** порядок вызовов конвейера — `LabPipeline` повторяет
`CameraExport.planTracks` из мода. В самом моде этот порядок намертво сцеплен с классами игры
(мир, метки реплея, настройки игрока), вынести его как есть нельзя. **Меняя порядок вызовов в
`CameraExport`, поправьте и `LabPipeline`** — иначе лаборатория начнёт показывать не то, что
уходит в реплей.

Два отличия от мода, оба намеренные:

- тики берутся из настроек темпа схемы (`ticksPerStep` слоя и пауза после него), а не из меток
  реплея — записи здесь нет;
- посторонние заслоны из мира (дерево, рельеф) не сканируются — мира здесь нет, только постройка.

## Файлы

```
camera-lab/
  build.gradle, settings.gradle   — отдельная сборка, к сборке мода не подключена
  corrections/                    — сюда ложатся пары «выбрал алгоритм / выбрал я»
  src/main/java/com/tutorialschematic/lab/
    CameraLab.java        — окно, управление, режим --report
    LabSchematic.java     — чтение .ltutorial без Minecraft
    LabPipeline.java      — прогон конвейера камер (зеркало CameraExport.planTracks)
    Scene3D.java          — отрисовка блоков проекцией самого алгоритма
    ViewPanel.java        — просмотр, оверлеи, свободный полёт, камеры как объекты
    TimelinePanel.java    — таймлайн: слои, сцены, ракурсы, мои правки
    ShotCorrections.java  — пары ракурсов и их разница: модель и файл
    LabReport.java        — числовой отчёт
```

Своя сборка и своя папка `build/` — с модом ничего не пересекается.
